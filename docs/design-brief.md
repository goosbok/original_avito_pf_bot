# Дизайн-бриф: Универсальная платформа цифровых услуг

> Документ для дизайнера / нейросети.
> Версия 2. Описывает концепцию продукта, архитектуру экранов, REST API и требования к масштабируемости.

---

## 1. Концепция продукта

### Суть

**Платформа** — личный кабинет и Telegram-бот для заказа цифровых маркетинговых услуг. Пользователь пополняет внутренний баланс и расходует его на услуги из каталога.

Сейчас реализовано:
- Продвижение объявлений на Авито (поведенческие факторы, SEO)
- Накрутка и удаление отзывов (Авито, ВКонтакте, Яндекс, 2ГИС, Flamp, Google)

В планах — любые цифровые услуги: копирайтинг, дизайн, SMM, ссылочное продвижение и т.д.

### Ключевые принципы для дизайна

1. **Каталог услуг — модульный.** Добавление новой услуги = добавление одной карточки в каталог и одной страницы оформления заказа. Глобальная структура не меняется.
2. **Нет жёсткой привязки к платформе.** Навигация и именование — нейтральные. «Заказать услугу», а не «Авито ПФ» на главном экране.
3. **Один компонент — одна ответственность.** Карточка услуги, форма заказа, история заказов — независимые блоки, которые переиспользуются на любой новой странице.
4. **Баланс — всегда виден.** Это главный ограничитель действий пользователя, он должен быть в шапке на каждом экране.

### Каналы доступа

| Канал | Стек | Аудитория |
|-------|------|-----------|
| **Telegram-бот** | aiogram 2.x, inline-кнопки, FSM | основной — мобильные пользователи |
| **Веб-кабинет** | FastAPI + vanilla JS, SPA-подход | дополнительный — десктоп и мобайл |
| **REST API** | JWT + ApiKey | разработчики, автоматизация |

### Монетизация

Все услуги оплачиваются с внутреннего баланса (₽). Пополнение: ЮКасса (автоматически) или вручную через менеджера. Реферальная программа: бонус рефереру при каждом пополнении привлечённого пользователя.

### Аутентификация

- Telegram OTP (код доставляется ботом)
- Email + пароль (bcrypt)

Оба провайдера можно привязать к одному аккаунту. Веб — JWT Bearer.

## 2. Дизайн-система

### 2.1 Принципы

- **Минимализм без пустоты.** Информация структурирована, но не перегружена. Каждый блок отвечает на один вопрос пользователя.
- **Контент масштабируется.** При добавлении 10 новых услуг каталог не превращается в стену. Используется сетка с ограничением по строкам и кнопкой «Все услуги».
- **Статусы всегда читаемы.** Цветовые бейджи для статусов заказа — единая система по всей платформе.
- **Форма ≠ страница.** Оформление заказа — это форма на отдельной странице, не модальное окно. Это упрощает мобильный UX.

| `ErrorAlert` | Инлайн-ошибка под формой или в верхней части карточки |

## 3. Структура экранов

### 3.1 Навигационная карта

```
/                        — Landing: выбор входа / регистрации
├── /login_telegram.html — Вход через Telegram OTP
├── /login.html          — Вход через Email
├── /register.html       — Регистрация через Email
└── /cabinet.html        — Личный кабинет (требует JWT)
    ├── /orders.html     — Полная история заказов
    ├── /pf-order.html   — Форма: заказ Авито ПФ
    └── [новые страницы] — Форма для каждой новой услуги
```

> **Принцип расширения:** новая услуга = новая карточка в каталоге + новый роут `/[service-slug]-order.html`. Шаблон формы переиспользуется, меняется только набор полей.

---

### 3.2 Landing (`/`)

**Цель:** быстро направить пользователя к нужному входу.

**Desktop:** карточка 420px по центру страницы, вертикальный список кнопок.
**Mobile:** те же кнопки, растянуты на всю ширину, отступы 16px.

Элементы:
- Логотип / название сервиса
- Подзаголовок (1 строка — что за сервис)
- Кнопка **«Войти через Telegram»** — Primary
- Кнопка **«Войти через Email»** — Secondary
- Кнопка **«Зарегистрироваться»** — Ghost / outline
- Скрипт: если `access_token` в localStorage — редирект в `/cabinet.html`

---

### 3.3 Вход / Регистрация

Все три страницы — одна карточка по центру, max-width 400px.

**Telegram OTP (`/login_telegram.html`):**
1. Поле «Username или номер телефона»
2. Кнопка «Получить код» → `POST /api/auth/telegram/request-code`
3. Поле «6-значный код» (появляется после успешного запроса)
4. Кнопка «Войти» → `POST /api/auth/telegram/verify-code`

**Email-вход (`/login.html`):**
1. Email, пароль, кнопка «Войти» → `POST /api/auth/email/login`
2. Ссылка «Зарегистрироваться»

**Регистрация (`/register.html`):**
1. Email, пароль (≥8 символов), имя (опц.)
2. Кнопка «Создать аккаунт» → `POST /api/auth/email/register`
3. Ссылка «Уже есть аккаунт»

---

### 3.4 Личный кабинет (`/cabinet.html`)

Главный экран после входа. Состоит из независимых блоков — каждый блок можно скрыть или переставить без влияния на остальные.

#### Шапка (sticky)
- Логотип / название (слева)
- `BalanceBadge` — «123 ₽», клик → скролл к блоку пополнения (справа)
- Имя пользователя + «Выйти» (справа)

**Mobile:** логотип + баланс в одну строку, имя/выход — в бургер-меню или под баланс.

#### Блок «Каталог услуг»
Сетка `ServiceCard` (3 колонки на десктопе → 2 на планшете → 1 на мобиле).

Каждая карточка:
- Иконка / иллюстрация (48×48)
- Название услуги
- 1 строка описания
- Цена «от X ₽» или «по тарифу»
- Весь блок — кликабельная ссылка на страницу заказа

Добавление новой услуги = добавить один объект в массив карточек. Максимум 6 карточек видны сразу, остальные — кнопка «Показать все».

#### Блок «Последние заказы»
Таблица из 5 строк + кнопка «Все заказы» → `/orders.html`.

Desktop: полная таблица с колонками `#, Услуга, Тариф, Сумма, Статус, Дата`.
Mobile: каждый заказ — карточка в одну колонку (accordion или flat card).

`EmptyState` если заказов ещё нет.

#### Блок «Пополнить баланс»
- Поле суммы (число, минимум — из настроек)
- Кнопка «Пополнить» → `POST /api/refill` → открывает `payment_url` в новой вкладке
- Polling `GET /api/refill/{id}/status` каждые 3 сек → показывает статус «Ожидание...» / «Зачислено!»

#### Блок «Поддержка»
Мини-чат, встроенный прямо в кабинет.
- Область сообщений 280px (скролл), polling `since_id` каждые 3 сек
- `ChatMessage`: user (справа, зелёный фон) / admin (слева, белый)
- Textarea + кнопка «Отправить» → `POST /api/support/messages`

---

### 3.5 История заказов (`/orders.html`)

Отдельная страница с полной таблицей.

Desktop: таблица с колонками `#, Услуга, Тариф, Сумма, Статус, Контакты, Дата, Ссылки`.
Mobile: список карточек (accordion: краткая строка → раскрыть детали).

Пагинация снизу: «← Предыдущая | Страница 1 из N | Следующая →».

Фильтр по статусу (Posted / Completed) — выпадающий список или таб-строка.

`EmptyState` с CTA «Заказать услугу» → `/cabinet.html`.

---

### 3.6 Форма заказа — шаблон

Каждая услуга имеет свою страницу с формой. Все формы используют одну раскладку:

```
┌─ Шапка: «← Назад»  |  Название услуги  |  Баланс ─────────┐
│                                                              │
│  ┌─ Карточка-форма (max-width 560px, центр) ──────────────┐ │
│  │                                                         │ │
│  │  [Поля, специфичные для услуги]                         │ │
│  │                                                         │ │
│  │  ┌─ PricePreview ──────────────────────────────────┐   │ │
│  │  │  Итого: X ₽  (обновляется в реальном времени)   │   │ │
│  │  └─────────────────────────────────────────────────┘   │ │
│  │                                                         │ │
│  │  [Кнопка «Разместить заказ»]                            │ │
│  └─────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

**Mobile:** форма растягивается на всю ширину, отступы 16px, кнопка «Разместить заказ» — sticky снизу экрана.

---

### 3.7 Форма заказа Авито ПФ (`/pf-order.html`)

Специфичные поля:
1. **Ссылки** — textarea «Вставьте ссылки на объявления avito.ru, по одной на строку». Под полем — счётчик «Найдено N ссылок»
2. **Дней** — слайдер 1–30 + числовое поле рядом
3. **Просмотров в день** — слайдер 5–100 + числовое поле рядом
4. **Показывать контакты** — toggle/checkbox с подписью
5. **PricePreview** → `price_per_unit × fix_count × days × links_count`

Ошибки:
- 402 → «Недостаточно средств. Пополните баланс»
- Невалидные ссылки → инлайн под полем

## 4. REST API

### Базовый URL: `http://host:8000`

#### Аутентификация
| Метод | Путь | Тело | Ответ | Описание |
|-------|------|------|-------|----------|
| POST | `/api/auth/email/register` | `{email, password, first_name?}` | `{access_token}` | Регистрация |
| POST | `/api/auth/email/login` | `{email, password}` | `{access_token}` | Вход email |
| POST | `/api/auth/telegram/request-code` | `{identifier}` | 204 | Отправить OTP |
| POST | `/api/auth/telegram/verify-code` | `{identifier, code}` | `{access_token}` | Проверить OTP |

#### Привязка провайдеров (JWT)
| Метод | Путь | Тело | Ответ | Описание |
|-------|------|------|-------|----------|
| POST | `/api/auth/link/email` | `{email, password}` | 204 | Привязать email |
| POST | `/api/auth/link/telegram/request-code` | `{identifier}` | 204 | OTP для привязки |
| POST | `/api/auth/link/telegram/verify-code` | `{identifier, code}` | 204 | Подтвердить привязку |
| DELETE | `/api/auth/link/{provider}/{identifier}` | — | 204 | Отвязать провайдер |

#### Профиль (JWT)
| Метод | Путь | Ответ | Описание |
|-------|------|-------|----------|
| GET | `/api/me` | `{user_id, user_name, first_name, balance}` | Текущий пользователь |
| GET | `/api/me/providers` | `[{provider, identifier, created_at, last_used_at}]` | Привязанные провайдеры |

#### Баланс (JWT или ApiKey)
| Метод | Путь | Тело | Ответ | Описание |
|-------|------|------|-------|----------|
| POST | `/api/refill` | `{amount}` | `{payment_id, payment_url}` | Создать платёж ЮКассы |
| GET | `/api/refill/{payment_id}/status` | — | `{payment_id, status}` | `pending` / `succeeded` / `failed` |

#### Заказы (JWT)
| Метод | Путь | Тело / Params | Ответ | Описание |
|-------|------|--------------|-------|----------|
| GET | `/api/orders/pf/price` | — | `{price_per_unit}` | Цена за единицу |
| GET | `/api/orders` | `?page=1&page_size=20` | `{items[], total, page, page_size}` | История заказов |
| POST | `/api/orders/pf` | `{links[], days, fix_count, contacts}` | `{order_id, total_price, status}` | Создать заказ ПФ |

`OrderItem`: `order_id, price, position_name, status, links, date, contacts`
Ошибки: `402` — нет денег, `404` — пользователь не в базе бота.

#### API-приложения (JWT)
| Метод | Путь | Тело | Ответ | Описание |
|-------|------|------|-------|----------|
| POST | `/api/applications` | `{name}` | `{id, name, api_key, api_key_prefix, created_at}` | Создать ключ (один раз) |
| GET | `/api/applications` | — | `[{id, name, api_key_prefix, created_at, revoked_at}]` | Список |
| DELETE | `/api/applications/{app_id}` | — | 204 | Отозвать |

#### Поддержка (JWT)
| Метод | Путь | Params | Ответ | Описание |
|-------|------|--------|-------|----------|
| GET | `/api/support/messages` | `?since_id=0` | `[{id, direction, text, created_at}]` | Сообщения (polling) |
| POST | `/api/support/messages` | — | 204 | Отправить сообщение |

`direction`: `"user"` / `"admin"`

#### Служебные
| Метод | Путь | Ответ |
|-------|------|-------|
| GET | `/api/health` | `{"status": "ok"}` |

## 5. Telegram-бот: сценарии

### Пользователь
| Действие | Сценарий |
|----------|---------|
| `/start` | Регистрация нового или главное меню |
| **Профиль** | Баланс, реферальная ссылка, список заказов, статус заказа |
| **Пополнить** | state `refill_balance` → выбор метода (ЮКасса / вручную) → confirm |
| **Заказ ПФ** | `tarifs:pf` → выбор тарифа → ввод ссылок → контакты → подтверждение + списание |
| **Отзывы** | выбор платформы → количество → ссылка → подтверждение |
| **SEO-буст** | количество месяцев → ссылка → подтверждение |
| **Промокод** | ввод кода → начисление баланса |
| Повторить заказ | восстановление ссылок предыдущего заказа |

### Администратор
| Действие | Описание |
|----------|----------|
| `/admin` | Панель: пользователи, заказы, промокоды, рассылка, настройки |
| Пользователи | Поиск по ID/username, пополнение/снятие баланса |
| Заказы | Просмотр, смена статуса, удаление (`/delete {id}`) |
| Промокоды | Создание (разовые / многоразовые), удаление |
| Рассылка | Broadcast всем пользователям |
| Настройки | Цены, тексты кнопок/сообщений, флаги оплаты, минимальная сумма |
| Уведомления | Автоматический форвард новых заказов и сообщений поддержки |

## 7. Адаптивность: требования

### Desktop (> 1024px)
- Шапка: одна строка, все элементы видны
- Кабинет: двухколоночная раскладка (каталог + история рядом) **или** одна колонка с секциями — на усмотрение дизайнера
- Таблицы заказов: все колонки развёрнуты
- Форма заказа: карточка по центру, max-width 560px

### Tablet (768–1024px)
- Шапка: логотип + баланс + выйти
- Каталог: 2 колонки
- Таблицы: 2 колонки скрыты (например, ссылки и контакты)

### Mobile (< 768px)
- Шапка: логотип + баланс (2 элемента), имя скрыто или под аватаром
- Каталог: 1 колонка, карточки полная ширина
- Таблица заказов → список карточек с accordion
- Форма заказа: поля стекируются вертикально, кнопка «Разместить» — sticky-footer
- Чат поддержки: полноэкранный overlay или отдельный экран

### Touch-friendly
- Минимальный tap target: 44×44px
- Слайдеры на форме ПФ: большой thumb (22px), достаточный зазор между слайдерами
- Нет hover-only состояний без touch-аналога

## 8. Расширяемость: как добавлять услуги

### Веб
1. Создать новый файл `[slug]-order.html` по шаблону из п. 3.6
2. Добавить объект в массив `SERVICES` в `cabinet.html` — карточка появится в каталоге автоматически
3. Добавить роутер в `web/routers/` и подключить в `web/main.py`

### Бот
1. Добавить обработчик в `handlers/` (новый файл)
2. Добавить кнопку в клавиатуру главного меню
3. Добавить строки текстов в `settings` таблицу

### Принцип: нет «богов» в коде и дизайне
- Не делать один «монстр»-экран со всеми услугами сразу
- Каждая услуга изолирована: своя страница, свой роутер, свой обработчик
- Общий каталог — только точка входа
