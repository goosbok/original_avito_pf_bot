# Welcome-бонус — дизайн

Дата: 2026-07-18
Статус: одобрено (вариант A — начисление в сервисном слое identity)

## Цель

Новым пользователям при регистрации (через бота или сайт) автоматически начисляется
приветственный бонус на баланс, чтобы можно было попробовать сервис бесплатно.
Сумма настраивается env-переменной в рублях.

## Конфигурация

- `WELCOME_BONUS_RUB` — env-переменная, целое число **рублей**.
  Читается в `data/config.py` (по паттерну существующих флагов), добавляется в `.env.example`.
- `0` или отсутствие переменной = фича выключена.
- Изменение суммы требует рестарта контейнера (как у остальных env-флагов).
- В БД баланс хранится в **копейках** → при начислении сумма умножается на 100.

## Начисление

Новый модуль `services/welcome_bonus.py`:

```
grant_welcome_bonus(user_id) -> int   # начисленные копейки; 0 = выключено или уже начислялся
```

Функция:
1. Если `WELCOME_BONUS_RUB <= 0` — выходит (0).
2. Идемпотентность: если в `refills` уже есть строка `source_type='welcome_bonus'`
   для этого юзера — выходит (0).
3. Кредитует баланс атомарно через `services/balance.credit`.
4. Пишет строку в `refills`: `amount` в копейках, `payment_id=NULL`,
   `source_type='welcome_bonus'`, `status='succeeded'` — история операции видна
   там же, где остальные пополнения.

### Точки вызова (только ветки создания настоящего нового юзера в `services/identity.py`)

| Точка | Канал | Бонус |
|---|---|---|
| `get_or_create_user_by_telegram` — ветка «genuinely new user» | бот `/start`, веб-логин через Telegram | да |
| `get_or_create_user_by_email` | регистрация на сайте по email | да |
| `find_or_create_user_by_phone` при `verified=True`, ветка нового юзера | вход по SMS на сайте | да |

### Кто НЕ получает бонус

- Гостевые phone-only юзеры (`find_or_create_user_by_phone` с `verified=False`,
  гостевой заказ на сайте) — иначе при мердже в полноценный аккаунт
  (`link_phone_provider` → `_merge_phone_only_into` складывает балансы) бонус задваивался бы.
- End-user'ы партнёрского API (`services/auth_api.py`, прямой `_create_user`).
- Legacy-юзеры, «пойманные» по старому `users.id == tg_id`.
- Все существующие на момент релиза пользователи (ретро-начислений нет).

## Совместимость с реферальным бонусом

`_is_first_refill()` (`services/refill.py:182`) определяет «первое пополнение» по
`refills WHERE status='succeeded'`. Welcome-запись обязана быть исключена:

```sql
... AND source_type != 'welcome_bonus'
```

Иначе welcome-запись занимает слот первого пополнения и реферер теряет 30% с первого
реального депозита приглашённого. Обратное направление безопасно: welcome-бонус не
проходит через `finalize_with_referral_bonus`, рефереру с него ничего не начисляется.

## Уведомление пользователя

- Бот: middleware `ExistsUserMiddleware._ensure_user` уже вычисляет `is_new` —
  дополнительно кладёт `data["is_new_user"]`. Хендлер `/start` при
  `is_new_user=True` и включённой фиче добавляет к приветствию строку
  «🎁 Вам начислен приветственный бонус N ₽».
- Сайт: без баннера — бонус просто виден в балансе (YAGNI).

## Схема БД

Без миграций: используются существующие таблицы `users` и `refills`.

## Тестирование

Unit-тесты (запуск в Docker, как принято в проекте):

1. Новый telegram-юзер → баланс = бонус, строка в `refills` с `source_type='welcome_bonus'`.
2. Новый email-юзер → бонус начислен.
3. Новый phone-юзер `verified=True` → бонус начислен.
4. Гостевой phone-юзер `verified=False` → бонуса нет.
5. API-юзер (`auth_api.authorize`) → бонуса нет.
6. Повторный `/start` существующего юзера → бонуса нет (и не задваивается).
7. `WELCOME_BONUS_RUB=0` / не задана → бонуса нет.
8. Реф-цепочка: новый юзер с welcome-бонусом делает первый реальный депозит →
   реферер получает 30% (проверка исключения welcome-записи из `_is_first_refill`).
9. Мердж phone-only гостя в полноценный аккаунт → итоговый баланс без двойного бонуса.
