# SMS-авторизация: подключение реального провайдера (TargetSMS)

**Дата:** 2026-07-26
**Провайдер:** TargetSMS (ООО «Таргет Телеком») — решение владельца проекта.

## Проблема

SMS-OTP вход на `lk.avito-pf.com` написан целиком, но не работает: нет реальной
отправки. Кнопка «По SMS» закомментирована в UI с 2026-06-07 с пометкой
«нужен provider integration».

Что уже готово и **не трогаем**:

| Слой | Файл | Состояние |
|---|---|---|
| API | `web/routers/auth_phone.py` | `/api/auth/phone/request-code`, `/verify`; TTL 5 мин, кулдаун 60 сек, JWT, реф-атрибуция |
| OTP | `services/otp.py` | `channel='sms'`, хеш кода с pepper, `MAX_ATTEMPTS=3` |
| Фронт | `web/static/components/PhoneLogin.jsx` | двухшаговая форма phone → code |
| Абстракция | `services/sms.py` | `SmsGateway` Protocol + `StubSmsGateway` |

Незакрыто ровно одно звено: реализация `SmsGateway`, отправляющая настоящие SMS.

## Какой именно API TargetSMS используем

У TargetSMS два подходящих на вид интерфейса. Берём **обычный JSON API
отправки**, а не их «СМС-авторизацию».

**Не используем** `http://apiagent.ru/password_generation/api.php`
(«СМС-авторизация», XML) по трём причинам:

1. Он генерирует код сам и возвращает его в ответе. У нас код генерирует
   `services/otp.py` — с солью, хранением только хеша, TTL и лимитом попыток.
   Чужой готовый код потребовал бы нового пути в OTP-сервисе ради функции,
   которая уже есть и работает.
2. Адрес — `http://` без TLS и на постороннем домене `apiagent.ru`
   (в заголовке документа при этом заявлен HTTPS). OTP открытым текстом.
3. Ошибки — только русский текст без кодов.

Обычный JSON API лишён всех трёх проблем: HTTPS, свой домен, наш код остаётся
нашим.

## Дизайн

### 1. `TargetSmsGateway` в `services/sms.py`

Новый класс рядом со `StubSmsGateway`, регистрируется в `get_gateway()` под
`SMS_GATEWAY=targetsms`. Ветка `else: raise ValueError` сохраняется: опечатка в
env падает, а не притворяется стубом.

Конфигурация через env, добавить в `.env.example`:

- `TARGETSMS_LOGIN`
- `TARGETSMS_PASSWORD`
- `TARGETSMS_SENDER` — согласованная подпись отправителя

Читаются при создании гейтвея. Отсутствие любого из трёх — `ValueError` при
инициализации, чтобы поломка конфига проявилась на старте, а не как 502 у
первого живого пользователя.

Транспорт — `httpx` (уже в `requirements.txt`, новых зависимостей нет).

**Контракт** (сверено по https://targetsms.ru/support/json/ 2026-07-26):

Endpoint: `https://sms.targetsms.ru/sendsmsjson.php`, метод **POST**.

```json
{
  "security": {"login": "...", "password": "..."},
  "type": "sms",
  "message": [{
    "type": "sms",
    "sender": "<TARGETSMS_SENDER>",
    "text": "<текст с кодом>",
    "abonent": [{"phone": "79001234567", "number_sms": "1"}]
  }]
}
```

Успех: `{"sms": [{"number_sms", "id_sms", "parts", "action"}]}`
Ошибка: `{"error": "<описание по-русски>"}`

Тем же endpoint доступны `type: "balance"` и `type: "state"` (статус доставки) —
в scope этой итерации не входят.

Значимые детали, каждая из которых иначе всплывёт в проде:

- **Формат телефона — без `+`.** `normalize_phone` (`utils/phones.py`) отдаёт
  `+79001234567`, TargetSMS ждёт `79001234567`. Ведущий `+` срезаем в гейтвее;
  сам `normalize_phone` не трогаем — от него зависит `otp.destination` и
  `identity`, менять его формат нельзя.
- **Ошибка приходит с HTTP 200.** Разбирать надо тело: наличие ключа `error`,
  а не статус ответа.
- **Числовых кодов ошибок нет**, только русский текст (`«Недостаточно
  средств»`, `«Аккаунт заблокирован»`, `«Текст SMS отклонен модератором»`).
  Поэтому: текст ошибки логируем дословно, а программную ветку делаем только
  на подстроку «недостаточно средств» и помечаем как best-effort — провайдер
  может переформулировать в любой момент.
- **Текст SMS обязан содержать название сервиса или сайта** — требование
  операторов к сообщениям с кодами авторизации, не прихоть провайдера.
- **Одинаковые запросы чаще раза в минуту отклоняются.** Нам это не мешает —
  код в каждом сообщении разный, тексты не совпадают, — но при отладке с
  фиксированным кодом легко на это напороться.

Ошибка провайдера транслируется в исключение; роутер уже ловит его и отдаёт
502 с логом (`auth_phone.py:56-59`).

### 2. Отправка не должна блокировать event loop

Сейчас в `web/routers/auth_phone.py:56` синхронный вызов внутри `async def`:

```python
sms.get_gateway().send_code(phone, code)
```

Со `StubSmsGateway` это запись в dict — безобидно. С реальным провайдером это
сетевой запрос прямо в event loop.

Это тот же класс отказа, который 2026-07-20 уронил бота на 8+ часов
(коммит `8b02e6c`): зависший синхронный запрос к YooKassa заморозил Telegram
polling, apscheduler и весь HTTP-трафик, причём без исключения, которое мог бы
поймать watchdog.

Решение — то же, что уже применено в `services/payment_reconciler.py` и в фиксе
refill:

- явный socket timeout на httpx-клиенте;
- вызов через `asyncio.to_thread` в роутере.

Протокол `SmsGateway` остаётся синхронным; асинхронность живёт в роутере.

### 3. Антиабьюз — осознанно не делаем

`POST /api/auth/phone/request-code` не требует авторизации, а кулдаун в
`otp.issue` работает по ключу `(channel, destination, purpose)`, то есть **на
номер телефона**. При платных SMS это означает: ротация номеров расходует
баланс без какого-либо ограничения, а исчерпанный баланс ломает вход по SMS
для всех.

Риск озвучен и **принят владельцем проекта**. Лимиты по IP и суточный потолок
в этой итерации не реализуются; единственная защита — существующий кулдаун
60 секунд на номер. К вопросу возвращаемся по реальному трафику.

Для протокола: TargetSMS в своей документации называет защиту формы
обязательной. Решение принято с учётом этого.

### 5. Тесты

Расширить `tests/unit/test_sms.py`:

- разбор успешного ответа (`{"sms": [...]}`);
- **HTTP 200 с телом `{"error": ...}` → исключение** (главный подводный камень:
  по статусу такой ответ неотличим от успеха);
- телефон уходит без ведущего `+`;
- текст ошибки попадает в лог дословно — иначе отладка «почему вход по SMS
  отвалился» упрётся в общий 502;
- отсутствие обязательного env → `ValueError` при инициализации;
- `_reset_for_tests()` продолжает работать.

Отдельный тест: роутер не блокирует event loop — по образцу
`tests/unit/test_refill_yookassa_offload.py`.

Запуск через `docker exec`, не локальным python.

## Экономика и порядок выката

Код и включение UI смержить можно сразу, но на проде `SMS_GATEWAY` остаётся
`stub`, пока не сделаны внешние шаги, от разработки не зависящие.

**Подпись отправителя — берём мультиподпись.** У TargetSMS она без платы за
подключение и без абонентской платы, одобряется быстро и рассчитана на объёмы
до 5–10 тыс. SMS/мес. Индивидуальная подпись стоит 1500–3000 ₽/мес за каждого
оператора (то есть 6–12 тыс. ₽/мес на четырёх) и оправдана только при
регулярных больших объёмах ради скидок на трафик.

**Риск при согласовании подписи:** имя со словом «avito» вряд ли одобрят —
это чужой товарный знак. Запасной вариант имени продумать заранее.

Трафик (с НДС, за 1 SMS): МТС 5,51 ₽, Теле2 7,46 ₽, остальные 9,73 ₽.
Минимального платежа нет, при регистрации дают 100 ₽ на тесты.

**Открытый вопрос к провайдеру:** с 2025-10 Билайн и Теле2, а с 2026-04
Мегафон/Yota перешли на пакетную тарификацию по уникальным абонентам за месяц.
Для OTP-профиля (почти каждый получатель уникален, 1–2 сообщения в месяц) это
может оказаться дороже поштучной модели. Уточнить до подписания договора.

Порядок:

1. регистрация в TargetSMS, согласование мультиподписи, пополнение баланса;
2. `SMS_GATEWAY=targetsms` + три `TARGETSMS_*` в env на проде.
