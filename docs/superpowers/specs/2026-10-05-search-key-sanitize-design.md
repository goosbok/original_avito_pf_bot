# Отбор поисковых ключей для автозапуска (sanitize) — Design

**Дата:** 2026-10-05
**Статус:** Approved (правила — заказчик, переписка 2026-10-04; решения по
нормализации — владелец, 2026-10-05)

## TL;DR

В базу для автозапуска больше не попадают мусорные поисковые ключи с
дашборда исполнителя. Единая функция `services/search_key.sanitize_search_key`
применяется на трёх входах: refresh кэша, classifier (hot-path dispatch'а) и
разовый cleanup-скрипт по историческим данным.

## Контекст

Кэш `avito_ad_phrase_cache` (ad_id → search_link) заполняется скрейпом
дашборда бизы — там лежит то, что заказчик вставлял при ручных запусках,
включая форс-мажорные. Правила заказчика — НЕ брать ключ в автозапуск, если:

1. **Ключ не начинается с https** — форс-мажор, прямой запуск в обход
   поиска («1», «#N/A»). Такое не должно лежать в базе автозапуска.
2. **В ссылке есть фильтр цены** (`priceMin`/`priceMax` в query) — ценовая
   вилка ломает накрутку («тупо не накрутит»).
3. **В ключе есть «;»** — при запуске вставили «ключ;ссылка_на_объяву»
   одной строкой, накрутка по такому не пойдёт.

Замер по продy (2026-10-05, 15 349 строк кэша): 5 942 (39%) с ценовым
фильтром, 69 не-https, 43 с «;». В `order_links.search_link` (что реально
ушло в бизу) — 2 412 задач с фильтром цены. Проблема уже живая.

### Решения владельца по правилам 2 и 3

Заказчик предлагал отбраковывать все три кейса. Владелец решил
нормализовать вместо отбраковки:

- ценовой фильтр **вырезается** из query (иначе потеряли бы 39% кэша);
- «ключ;ссылка» **разбирается**, берётся поисковая https-часть.

Отбраковывается только то, что нормализовать нельзя: не-https и «;» без
https-части.

## Изменения

### `services/search_key.py` (новый)

`sanitize_search_key(raw) -> (clean | None, action)`. Порядок: trim →
разбор «;» (предпочитаем avito.ru-часть) → проверка https-префикса →
вырезание `price`/`priceMin`/`priceMax` из query.

Вырезание price-параметров — **строковое** (split query по `&`, выкинуть
пары по ключу), а не parse_qsl/urlencode: пересборка перекодирует
кириллицу в %XX, а ключи в БД и у исполнителя лежат в исходном виде.

Actions: `ok` / `price_stripped` / `semicolon_split` /
`semicolon_price_fixed` / `empty` / `not_https` /
`semicolon_no_https_part`.

### `services/avito_phrase_cache_refresh.py`

Каждая строка дашборда прогоняется через sanitize **до** группировки
latest-wins. Невалидная → skip + warning `biza.refresh.skip_invalid_key`.
Это главная точка: форс-мажорный запуск больше не затирает хороший ключ
(latest-wins работает только среди валидных).

### `services/order_links_classifier.py`

Новая `resolve_phrase(ad_id) -> (phrase | None, source)`:
кэш → fallback в историю `order_links.search_link` этого же объявления
(последние 20, новые первыми) → `cache_miss`. Фраза из любого источника
прогоняется через sanitize. Source codes: `cache_hit` / `history_hit` /
`cache_miss`; невалидный ключ кэша логируется `classifier.invalid_cache_key`.

`classify()` переходит на `resolve_phrase` — контракт (mode, phrase)
неизменен, dispatcher не трогаем. `classify_for_preview` в dispatcher'е
тоже на `resolve_phrase` — preview совпадает с реальным решением.

Замер прода: fallback в историю спасает лишь 4 из 342 битых объявлений —
оставлен как best-effort, основной путь «нет ключа → manual» (ручной
запуск заказчиком), что соответствует требованию.

### `scripts/cleanup_phrase_cache.py` (новый)

Разовый прогон по существующему кэшу. Dry-run по умолчанию, `--apply`
пишет: нормализованные ключи обновляет в месте, невалидные удаляет.
Идемпотентен. Ожидаемый эффект по проду: ~5,9k обновлений, ~342 удаления.

Историю `order_links.search_link` сознательно **не** трогаем — это факт
«что реально отправили», а не источник для будущих запусков.

## Тесты

- `test_search_key.py` — все ветки sanitize (16 кейсов);
- `test_order_links_classifier_sanitize.py` — нормализация ключа из кэша,
  fallback в историю, source codes;
- `test_avito_phrase_cache_refresh.py` — skip невалидных, strip цены,
  latest-wins среди валидных, разбор «;»;
- обновлены фикстуры старых тестов: текстовые фразы («купить квартиру»)
  заменены на https-URL — по новым правилам текст невалиден.

## Раскатка

1. Deploy на сервер (git pull + restart контейнеров).
2. `docker compose exec api python -m scripts.cleanup_phrase_cache` —
   проверить dry-run статистику.
3. То же с `--apply`.
